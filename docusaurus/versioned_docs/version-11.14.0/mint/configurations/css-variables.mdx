Mint uses a **three-layer theming system** built on CSS custom properties and Tailwind CSS v4. Understanding this architecture makes it straightforward to apply your own branding.

## Architecture Overview

```text
src/themes/chapsvision.css          src/theme.css
─────────────────────────           ─────────────────────────────
Layer 1 · Color Palette             Layer 3 · Tailwind Mapping
  @theme {                            @theme inline {
    --color-sage-800: #445556;          --color-primary: var(--primary);
    --color-pink-200: #efc9f3;          --color-accent:  var(--accent);
    ...                                 ...
  }                                   }
                                    ↓
Layer 2 · Semantic Tokens           Tailwind utility classes
  :root {                             bg-primary, text-accent,
    --primary: var(--color-sage-800);  border-secondary, ...
    --accent:  var(--color-pink-200);
    ...
  }
  .dark {
    --primary: var(--color-sage-200);
    ...
  }
```

| Layer | File | Purpose |
|-------|------|---------|
| **1 – Color Palette** | `src/themes/chapsvision.css` (`@theme` block) | Raw color scales (`--color-sage-*`, `--color-pink-*`, …). These are the building blocks. |
| **2 – Semantic Tokens** | `src/themes/chapsvision.css` (`:root` / `.dark`) | Maps palette colors to roles (`--primary`, `--accent`, `--sidebar`, …). Change these for branding. |
| **3 – Tailwind Mapping** | `src/theme.css` (`@theme inline`) | Exposes semantic tokens as Tailwind utilities (`bg-primary`, `text-accent`, …). Do not edit unless adding new utilities. |

## Customizing Your Branding

To apply custom branding, **override the semantic tokens** (Layer 2) in your own CSS file — you never need to touch `chapsvision.css` directly or re-declare the full palette.

### Minimal Override

Create or edit `src/styles/custom-theme.css` (imported after `theme.css`):

```css
:root {
  /* Your brand primary color */
  --primary: #1a56db;
  --primary-foreground: #ffffff;

  /* Your brand accent color */
  --accent: #e0f2fe;
  --accent-foreground: #0c4a6e;

  /* Sidebar & header */
  --sidebar: #1e3a5f;
  --header: #1e3a5f;
}

.dark {
  --primary: #93c5fd;
  --accent: #1e3a5f;
}
```

| Token | Role | Light default |

## Light & Dark Mode

Mint uses a **class-based dark mode** — the `.dark` class is applied to the `<html>` element. The semantic tokens are declared twice:

- `:root` → light mode values
- `.dark` → dark mode overrides

```css
:root {
  --primary: var(--color-sage-800); /* #445556 */
}

.dark {
  --primary: var(--color-sage-200); /* #d1e1dd */
}
```

When overriding, always provide both blocks to keep dark mode working correctly.

:::note Chrome `light-dark()` workaround
The CSS `light-dark()` function has a bug in Chrome (as of early 2026). Avoid using it for semantic token values. Use explicit `:root` / `.dark` declarations instead, as done throughout `chapsvision.css`.
:::

## Tailwind Utilities

Once defined in `src/theme.css`, every semantic token becomes available as Tailwind classes:

| Semantic token | Tailwind classes generated |
|----------------|---------------------------|
| `--primary` | `bg-primary`, `text-primary`, `border-primary`, `ring-primary` |
| `--primary-foreground` | `bg-primary-foreground`, `text-primary-foreground`, … |
| `--accent` | `bg-accent`, `text-accent`, … |
| `--sidebar` | `bg-sidebar`, `text-sidebar`, … |
| `--destructive` | `bg-destructive`, `text-destructive`, … |

The full mapping is in `src/theme.css inside the`@theme inline` block.
